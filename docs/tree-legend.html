What the shapes in the tree mean

Every marker gitstat draws in the tray strips and in the big column view, drawn here with the app's own colours. It follows your light or dark theme like the app does.

Commit dots

Filled dot
A commit. Its colour says what kind (see Colours below). The lines between dots are parent links.
Dot with a soft halo
HEAD: the commit you have checked out. In the column view its hash is also bold.
Blue ring
A commit on the remote that you haven't pulled yet.
Small ring where lines join
A merge commit. Its ring is a little smaller than the not-pulled ring.
Dashed amber ring
Uncommitted changes in the working folder. It sits just right of HEAD, joined by a dashed line.
Thin outer ring, briefly
You clicked the dot and its commit id went to the clipboard.
Faded dot and line
A branch past the fifth lane. Extra lanes are folded onto the outer edge and dimmed.

Marks next to a dot

Small diamond above
The commit has a tag. Every build pushes a build/<n> tag, so most built commits carry one.
Hollow square on a dotted line
A stash made on top of that commit.
Soft wide band under a line
Another worktree of the same repo is checked out on that line. The band starts at its checked-out commit.

In the big column view the tag and stash marks aren't drawn on the graph. They show as labels beside the row instead (see Column view below).

Colours

Grey
On the default branch (main).
Amber
Committed here but not pushed yet.
Blue
On the remote, not pulled yet (drawn as a ring).
Purple
Merged into the default branch, or its pull request was merged.
Green
The branch has an open pull request.
Pale grey
The branch has a draft pull request. It's kept a different grey from main's.
Red
The branch's pull request was closed without merging.
Other hues
Any other branch. Each branch gets one of six colours picked from its name, so it keeps the same colour every time.

Pull request colours win over the rest: a branch with an open PR is green even if some of it is unpushed.
